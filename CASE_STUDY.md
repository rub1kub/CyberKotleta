# CyberKotleta Core — разбор проекта

## Контекст

CyberKotleta Core создавался для живого Discord-сервера, где нужны были не демо-команды, а реальные инструменты автоматизации: роли, статистика, уровни, репутация и динамические роли по состоянию пользователя.

Проект начался как быстрый вайбкодинг, но был доведён до состояния, которое можно спокойно выкладывать публично: секреты вынесены, runtime-файлы игнорируются, структура модульная, запуск и настройка описаны.

## Задача

Ручное управление Discord-сервером плохо масштабируется:

- кастомные роли нужно валидировать и безопасно выдавать;
- роли-разделители сбиваются при изменениях ролей участников;
- время в голосовых каналах сложно учитывать вручную;
- уровни и репутация требуют постоянного хранения данных;
- роли за тег сервера и присутствие в войсе должны синхронизироваться автоматически.

## Решение

Бот разделён на независимые cogs:

- `custom_roles` — кастомные роли и разделители;
- `stats_voice` — учёт времени в голосовых каналах;
- `stats_messages` — сообщения и начисление опыта;
- `stats_commands` — команды статистики;
- `levels` — уровни и таблица лидеров;
- `reputation` — репутация за ответы и реакции;
- `server_tag_role` — роль за отображаемый тег сервера;
- `voice_presence_role` — роль для пользователей, которые сейчас находятся в войсе;
- `voice_king` — недельный отбираемый титул для лидера войса.

## Инженерные решения

- **Асинхронные события Discord:** бот реагирует на вход/выход из войса, сообщения, реакции и slash-команды.
- **Периодическая синхронизация:** фоновые задачи исправляют рассинхрон после рестарта или пропущенного события.
- **Отбираемые статусы:** Войс-царь не выдаётся навсегда, а переходит к активному участнику в войсе, который обогнал текущего лидера; при равном времени используется алфавитный tie-breaker.
- **Видимый flex:** название роли Войс-царя содержит часы за неделю, чтобы статус был виден прямо в списке ролей.
- **Честная недельная статистика:** Войс-царь считается только по текущей неделе, без lifetime-часов.
- **SQLite:** лёгкая база подходит для такого масштаба и не усложняет деплой.
- **Конфигурация через `.env`:** токены и ID сервера не лежат в публичном коде.
- **Разделение по cogs:** каждую функцию можно дорабатывать отдельно.
- **Гигиена репозитория:** база, логи, токены, venv и cache не попадают в Git.

## Вайбкодинг-подход

В проекте использовался быстрый AI-assisted workflow:

1. сформулировать нужную фичу;
2. быстро получить рабочий вариант;
3. проверить на реальном Discord-сервере;
4. посмотреть логи;
5. исправить edge cases;
6. привести код к читаемой структуре;
7. задокументировать и запушить.

Это ускоряет разработку, но не отменяет инженерную проверку.

## Что демонстрирует проект

- Практическую интеграцию с Discord API.
- Асинхронную разработку на Python.
- Работу с состоянием через SQLite.
- Аккуратное управление ролями и правами.
- Эксплуатационное мышление: логи, фоновые задачи, восстановление после рестарта.
- Безопасную подготовку проекта к публичному GitHub.
